  <files>electron/database/schema.ts, tests/database.test.ts</files>
  <behavior>
    - Schema exports notes table with id, title, body, metadata, created_at, updated_at, deleted_at columns
    - Schema exports tags table with id, name, created_at columns (name is unique)
    - Schema exports noteTags junction table with composite primary key (note_id, tag_id)
    - Schema exports links table with id, source_note_id, target_note_id, created_at columns
    - Schema exports noteVersions table with id, note_id, title, body, metadata, version_number, created_at columns
    - All foreign keys have proper ON DELETE behavior (CASCADE for note_tags/links, CASCADE for note_versions)
    - deleted_at column is nullable integer (timestamp for soft delete)
  </behavior>
  <action>
Create Drizzle ORM schema per D-02 (user locked database schema design). Use TEXT for IDs (UUIDs), INTEGER for timestamps (Unix epoch), TEXT for JSON metadata blobs.

Schema structure from CONTEXT.md:
- notes: id (PK), title, body, metadata (JSON), created_at, updated_at, deleted_at (nullable)
- tags: id (PK), name (unique), created_at
- note_tags: note_id (FK), tag_id (FK), composite PK
- links: id (PK), source_note_id (FK), target_note_id (FK), created_at
- note_versions: id (PK), note_id (FK), title, body, metadata, version_number, created_at

Foreign key cascade rules:
- note_tags: ON DELETE CASCADE (delete tag associations when note deleted)
- links: source ON DELETE CASCADE, target ON DELETE SET NULL (preserve link record if target deleted, show as broken)
- note_versions: ON DELETE CASCADE (delete version history when note deleted)

Write tests first (TDD): verify table exports exist, verify column types, verify foreign key constraints, verify unique constraint on tags.name.
  </action>

    <automated>npm test tests/database.test.ts -t "schema" -x</automated>
  </verify>
  <done>Drizzle schema defines all 5 tables with correct columns, types, and foreign key constraints. Tests verify schema structure. Schema matches CONTEXT.md locked design.</done>

Three FTS5 tables from CONTEXT.md:

All use content='notes' and content_rowid='rowid' to reference main table (no data duplication).

Create triggers for INSERT, UPDATE, DELETE to keep FTS5 tables in sync. Create indexes per RESEARCH.md Pattern 2 for sub-100ms search requirement (KNOW-04).

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Main process → SQLite file | Database file stored in OS-protected userData directory, no renderer access |
| Drizzle ORM → SQLite | Parameterized queries prevent SQL injection |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Tampering | SQLite database file | accept | File in userData directory (OS-protected), user can tamper own data |
| T-02-02 | Information Disclosure | Database path in logs | mitigate | Never log full database path, use relative path in error messages |
| T-02-03 | Denial of Service | Database file corruption | mitigate | Enable WAL mode for crash recovery, validate schema on startup |
| T-02-04 | Tampering | SQL injection via Drizzle | mitigate | Use Drizzle ORM parameterized queries exclusively, never string concatenation |
| T-02-SC | Tampering | npm/pip/cargo installs | mitigate | All packages passed slopcheck verification (RESEARCH.md Package Legitimacy Audit) |
</threat_model>
