<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| npm registry → user's machine | Package tarball downloaded from npm, must not contain secrets or malicious code |
| User input → package.json files field | Whitelist controls what gets published, prevents accidental secret leakage |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Information Disclosure | package.json files field | mitigate | Use explicit whitelist (bin/, electron/, dist/, README.md) to prevent publishing .env, .git, test files, or source TypeScript |
| T-04-02 | Tampering | optionalDependencies | mitigate | Mark Electron packages as optional so install continues if Electron download fails (prevents install failures on restricted networks) |
| T-04-03 | Denial of Service | engines field | mitigate | Specify minimum Node.js 18.0.0 to prevent cryptic errors on old Node.js versions lacking ESM support |
| T-04-04 | Tampering | TypeScript compilation | accept | Compiled .js files shipped in package, source .ts files excluded via files whitelist (standard npm pattern, low risk) |
| T-04-SC | Tampering | npm/pip/cargo installs | mitigate | slopcheck + blocking human checkpoint for [ASSUMED]/[SUS] packages (per Package Legitimacy Gate protocol) |
</threat_model>
