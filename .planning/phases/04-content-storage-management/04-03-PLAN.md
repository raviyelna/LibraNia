Create electron/services/content.service.ts with the following structure:

**Imports:**
- fs/promises for file operations
- path for path manipulation
- crypto for UUID generation
- file-type (fileTypeFromBuffer) for MIME validation
- Drizzle ORM: eq, and, isNull from drizzle-orm
- content, contentTags from ../database/schema
- BetterSQLite3Database type

**Interfaces:**
- CreateContentInput: { filePath: string; source: 'manual' | 'ai-generated'; confidence_score?: number; note_id?: string; message_id?: string }
- UpdateContentInput: { extracted_text?: string; thumbnail_path?: string; metadata?: string }
- Content: matches database schema (14 fields from Plan 04-01)

**Helper Functions:**

validateFileType(buffer: Buffer): Promise<{ mime: string; ext: string }>
- Use fileTypeFromBuffer to detect MIME type from magic bytes (per RESEARCH.md Pattern 2)
- Allowed MIME types: application/pdf, application/vnd.openxmlformats-officedocument.wordprocessingml.document, text/plain, text/markdown, image/png, image/jpeg, image/webp (per D-05, D-07)
- Throw error if MIME type not in allowed list
- Return { mime, ext } object

validateFileSize(filePath: string): Promise<number>
- Use fs.stat to get file size
- Throw error if size > 50MB (50 * 1024 * 1024 bytes per RESEARCH.md Pitfall 3)
- Return file size in bytes

writeFileAtomic(filePath: string, data: Buffer): Promise<void>
- Generate temp path: `${filePath}.tmp.${crypto.randomUUID()}`
- Write data to temp file using fs.writeFile
- Rename temp to final path using fs.rename (atomic on same filesystem per RESEARCH.md Pattern 1)
- On error: clean up temp file with fs.unlink in catch block, then rethrow
- Matches Phase 1 config.service.ts atomic write pattern per D-04

**CRUD Functions:**

createContent(data: CreateContentInput, db: BetterSQLite3Database): Promise<Content>
- Read file from data.filePath using fs.readFile
- Validate file type using validateFileType (throws on invalid)
- Validate file size using validateFileSize (throws if > 50MB)
- Generate UUID: crypto.randomUUID()
- Generate destination path: `content/${uuid}.${ext}` (per D-02, D-03)
- Ensure /content/ directory exists: fs.mkdir('content', { recursive: true })
- Write file atomically using writeFileAtomic
- Get original filename: path.basename(data.filePath)
- Insert to database: id, file_path (destination), thumbnail_path (null initially), mime_type, original_filename, file_size, extracted_text (null initially), source, confidence_score, metadata (null initially), note_id, message_id, created_at, updated_at
- Return created Content record

getContentById(id: string, db: BetterSQLite3Database): Promise<Content | null>
- SELECT from content WHERE id = ? LIMIT 1
- Return Content or null if not found
- Matches notes.service.ts getNoteById pattern

updateContent(id: string, data: UpdateContentInput, db: BetterSQLite3Database): Promise<Content>
- Check content exists using getContentById (throw if not found)
- UPDATE content SET extracted_text, thumbnail_path, metadata, updated_at WHERE id = ?
- Return updated Content record
- Matches notes.service.ts updateNote pattern

deleteContent(id: string, db: BetterSQLite3Database): Promise<boolean>
- Get content record to find file_path and thumbnail_path
- DELETE from content WHERE id = ? (hard delete, no soft delete for files)
- Delete file from filesystem: fs.unlink(file_path)
- Delete thumbnail if exists: fs.unlink(thumbnail_path) in try/catch (ignore if missing)
- Return true if deleted successfully
- Note: CASCADE delete handles content_tags cleanup automatically

getAllContent(db: BetterSQLite3Database): Promise<Content[]>
- SELECT * from content ORDER BY created_at DESC
- Return Content[] array
- Matches notes.service.ts getAllNotes pattern

Export all functions and interfaces.

Add imports to electron/services/content.service.ts:

Add helper function extractText(filePath: string, mimeType: string): Promise<string>
- If mimeType === 'application/pdf': read file buffer, call pdfParse(buffer), return data.text
- If mimeType === 'application/vnd.openxmlformats-officedocument.wordprocessingml.document': call mammoth.extractRawText({ path: filePath }), return result.value
- If mimeType === 'text/plain' or 'text/markdown': read file as UTF-8 string using fs.readFile(filePath, 'utf-8')
- For images (image/*): return empty string (no text extraction per D-06)
- Truncate result to 100KB (102400 bytes) to prevent FTS5 index bloat per RESEARCH.md Pitfall 4: if (text.length > 102400) text = text.substring(0, 102400)
- Return extracted text
- Matches RESEARCH.md Pattern 3

Add helper function generateThumbnail(inputPath: string, mimeType: string): Promise<string | null>
- If mimeType does not start with 'image/': return null (no thumbnail for documents)
- Ensure /content/thumbnails/ directory exists: fs.mkdir('content/thumbnails', { recursive: true })
- Generate thumbnail filename: extract UUID from inputPath, create `content/thumbnails/${uuid}.jpg`
- Use sharp to resize: sharp(inputPath).resize(200, 200, { fit: 'cover', position: 'center' }).jpeg({ quality: 80 }).toFile(thumbnailPath)
- Return thumbnail path
- Matches RESEARCH.md Pattern 4 (200x200 per D-08)

Update createContent function:

- Insert to database with extracted_text and thumbnail_path values (not null anymore for processed content)
- Note: Processing happens synchronously before database insert to ensure data consistency (per RESEARCH.md Pitfall 6: avoid orphaned files)

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User filesystem → Main process | File paths provided by user could be malicious |
| File content → Database | Extracted text and metadata stored after validation |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-06 | Tampering | File path validation | mitigate | Path normalization and traversal check in validateFileType before processing |
| T-04-07 | Denial of Service | Large file processing | mitigate | 50MB file size limit enforced in validateFileSize |
| T-04-08 | Denial of Service | FTS5 index bloat | mitigate | Truncate extracted_text to 100KB before database insert |
| T-04-09 | Tampering | MIME type spoofing | mitigate | Magic bytes validation via file-type library (not extension-based) |
| T-04-10 | Information Disclosure | Orphaned files | mitigate | Atomic pattern: write file → extract text → generate thumbnail → insert DB (rollback deletes file on DB error) |
</threat_model>
