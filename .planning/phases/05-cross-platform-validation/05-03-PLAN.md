## Prerequisites

**Ubuntu 22.04 LTS environment:**
- Physical machine, VM, or WSL2 with Ubuntu 22.04 LTS
- Node.js 18+ installed
- Build tools: `sudo apt install build-essential python3`

**Windows 10 environment:**
- Physical machine or VM with Windows 10
- Node.js 18+ installed
- Visual Studio Build Tools installed (https://visualstudio.microsoft.com/downloads/#build-tools-for-visual-studio-2022)
- Test in cmd.exe (not PowerShell) per D-02

## Test Protocol

### Phase 1: Package Installation (Both Platforms)

**On Ubuntu 22.04:**
```bash
# Navigate to LibraNia repo
cd /path/to/LibraNia

# Create package tarball
npm run build:package
npm pack

# Install globally from tarball
npm install -g librania-*.tgz

# Verify installation
librania --version
librania --help
```

**On Windows 10 (cmd.exe):**
```cmd
REM Navigate to LibraNia repo
cd C:\path\to\LibraNia

REM Create package tarball
npm run build:package
npm pack

REM Install globally from tarball
npm install -g librania-*.tgz

REM Verify installation
librania --version
librania --help
```

**Expected results (both platforms):**
- `npm install -g` completes without errors
- Postinstall script rebuilds better-sqlite3 and sharp successfully
- `librania --version` shows current version (e.g., 2.0.0)
- `librania --help` shows usage instructions

**If postinstall fails:**
- Error message should show platform, Node version, and build tool installation instructions (from Plan 05-02)
- Verify error message format matches D-12 specification

### Phase 2: CLI Execution (Both Platforms)

**On Ubuntu 22.04:**
```bash
# Start server with default settings
librania start

# Verify:
# - Server starts on port 3000
# - Browser opens automatically to http://localhost:3000
# - No errors in console
# - Frontend loads successfully

# Stop server (Ctrl+C)
# Verify graceful shutdown message appears

# Test custom port
librania start --port 3001

# Test headless mode
librania start --no-browser

# Test custom data directory
librania start --data-dir ~/librania-test
```

**On Windows 10 (cmd.exe):**
```cmd
REM Start server with default settings
librania start

REM Verify:
REM - Server starts on port 3000
REM - Browser opens automatically to http://localhost:3000
REM - No errors in console
REM - Frontend loads successfully

REM Stop server (Ctrl+C)
REM Verify graceful shutdown message appears

REM Test custom port
librania start --port 3001

REM Test headless mode
librania start --no-browser

REM Test custom data directory
librania start --data-dir %USERPROFILE%\librania-test
```

**Expected results (both platforms):**
- CLI starts server successfully
- Browser opens automatically (unless --no-browser used)
- Server responds at http://localhost:PORT
- Graceful shutdown on Ctrl+C
- Custom port and data directory flags work correctly

### Phase 3: Path Edge Cases (Both Platforms)

**On Ubuntu 22.04:**
```bash
# Test tilde expansion
librania start --data-dir ~/librania-tilde-test

# Test absolute path
librania start --data-dir /tmp/librania-absolute-test

# Test path with spaces
librania start --data-dir "$HOME/librania test with spaces"

# Test relative path
librania start --data-dir ./librania-relative-test
```

**On Windows 10 (cmd.exe):**
```cmd
REM Test environment variable
librania start --data-dir %USERPROFILE%\librania-env-test

REM Test drive letter
librania start --data-dir D:\librania-drive-test

REM Test path with spaces
librania start --data-dir "C:\Program Files\librania test"

REM Test relative path
librania start --data-dir .\librania-relative-test
```

**Expected results (both platforms):**
- All path formats resolve correctly
- Data directories created at expected locations
- Database file created in correct subdirectory (data/librania.db)
- No path separator errors (no mixing of / and \)

- All tests pass on both Ubuntu 22.04 and Windows 10

- CLI doesn't start on either platform
- Native modules fail to compile or run
- Path edge cases cause errors
- Error messages lack platform context
